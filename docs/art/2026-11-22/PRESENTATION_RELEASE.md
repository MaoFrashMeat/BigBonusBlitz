# 冒険の接地・飛翔・路面（dev 420）

制作は2026年11月22日、統合検証は11月23日。背景は前版で全30地点に原画を配置済み。今回は共通路面と中景の境界、サリアの歩行と大槌、敵の射撃を本編で修正した。

## 本編の挙動

- 通常歩行の基体8枚と槍歩行8枚に支持足の位置を登録。足の裏から膝までを頂点で分割し、同じ原画を保持する間、接地側の靴を路面速度に合わせて動かす。胴、武器、手の絵は元の形を保つ。モーダル中は路面の歩行スクロールも止まる。接近の最後は構え入りまでに前進を終える。
- 大槌の低い敵用に6姿勢を追加。二つの握りの向きから柄を回転し、描画と到達点の計算に同じ姿勢を使う。初稿では槌頭がスライムの足元より下に出た。接触コマの実画像で手の位置を取り直し、槌頭がスライム側面に入る高さに修正した。[原画](hammer-low.png)・[生成プロンプト](hammer-low-prompt.txt)
- 魔導書と熾火トカゲは離れた位置から発射する。発射時点の敵の絵からサリアの現位置まで飛ばし、着弾で既存の戦闘結果演出に渡す。敵の退場・別動作で飛翔を取り消す。抽選やHPの更新は既存の処理で行う。弾にはリポジトリにある `tools/fx-lab/textures/bolt.png` と `flame_a.png` を使用した。
- 筆跡を持つ路面を中景と前景の間に置き、奥縁を透過させた。地域ごとの地色と時刻・天候の光を受ける。[路面原画](road-grain.png)・[生成プロンプト](road-grain-prompt.txt)

## 発見した問題と再検証

1. 低姿勢から復帰する検査は最初の1.5秒で終了し、大槌だけ後退途中だった。観測を3秒に延ばし、5武器×3敵で接触が各1回、後退終了時に原点・通常姿勢へ戻ることを確認した。
2. UnityのJSON読み込みでは未指定の射撃データが空のオブジェクトになることがあり、近接敵の踏み込みを失い、空の画像名を参照した。画像名・寸法・飛翔時間を満たす敵だけが射撃を使うよう修正。20敵を本編に出す試験にも発射・着弾・近接距離の検査を追加した。
3. 最初の背景検査では360条件と周期検査が通ったが、草原の道がほぼ単色だった。共通インポーターが路面を通常テクスチャに戻していた。路面を単一スプライト・横リピートで読み、路面のみを描いて濃淡とスクロールによる画素変化を検査した。
4. Windows用の最初の隔離コピーでは転送完了前にUnityが起動し、パッケージとアセンブリの参照に失敗した。新しい隔離先でプロジェクトと依存パッケージの転送を終えてからビルドを実行した。

## 描画検査

[検証用ファイル](../../../tools/environment-qa/2026-11-23/verified/)には近接の実時間動画、大槌の接触、2種の弾、草原・書庫・洞窟の実描画、計測結果を保存した。動画は隔離Unityの120 Hz再生を4フレームに1枚ずつ収録し、30 fpsで再生するもの。本編のリール連動とヒットの結果は別のGameController試験で確認した。

- 接触15組、槍歩行8枚、接地16枚、遠隔2種。支持足検査は各コマ保持中の足元と路面の水平変位、上体の変位を比較する。コマ切替の印象は動画で確認する。
- 背景全30地点を朝・昼・夕・夜と9天候で描画し、1,080条件で屋内の天候変換を含めて確認。正逆3周、3層、30地点の540境界を計測し、各地点の本編画面を1280×720と2556×1179で保存した。原画の画素にアルファを持つ29地点と、マットから透明度を復元するC-1を含む。
- 再実行は既存の隔離shop-qaに本編Assetsを同期し、`SupportContactValidation.Run`、`NativeEnvironmentValidation.Run`、EditMode全件を使う。実測値・画像の出力先はそれぞれ `SUPPORT_CONTACT_OUTPUT`、`NATIVE_ENVIRONMENT_OUTPUT`、`ENEMY_GAMEPLAY_OUTPUT`・`ENEMY_REEL_OUTPUT`・`HERO_JOURNEY_OUTPUT` で指定する。

## Windowsプレイヤー

Unity 6000.3.15f1で、リリース用作業ツリーのAssets・Packages・ProjectSettingsを新しい隔離先に複製した。製品名を `shop-qa`、会社名を `BBBPresentationQA` として保存先を分離した。[ビルド処理](../../../tools/environment-qa/PresentationPlayerBuild.cs)は隔離先で有効なシーンをWindows 64ビットにビルドする。

追加の[操作試験](../../../tools/environment-qa/StandalonePresentationSmoke.cs)を入れた計測用プレイヤーでは、検証用セーブを作ってタイトル→街→冒険→BETと進み、リールの開始を確認した。非表示ウィンドウの通常キャプチャでは透明画像を返したため、その画像は破棄した。実行中のルートCanvasを検査カメラに接続して明示的に描画し、空画像を検出する判定を通して4画面を保存した。入力は各ボタンのリスナー経由で、実マウスのクリックではない。通常プレイヤーにはこの検査コードを含めない。

Windowsで音声ソースの初期化中に空クリップの自動再生警告を10件確認。非アクティブなオブジェクト上でBGM・SE・動作用ソースを設定した。続いて声音・選択音の遅延追加時にも同種の警告が出たため、これらも有効化前に設定した。再実行で同種の警告は0件。冒険BGMの再生クリップは `bgm_adventure`。

[Windows計測](../../../tools/environment-qa/2026-11-23/verified/player.json)は1280×720、Direct3D 12、Ultra、RTX 4070 Ti、i7-13700KF。冒険画面の240フレームの中央値・95百分位はともに約8.33 ms。フレーム間隔の短時間測定であり、GPU単体の時間・全ステージ戦闘時の最低fps・携帯端末性能は未計測。

他のAIは同じ隔離製品名・会社名で `PresentationPlayerBuild.Run` を実行できる。ビルド先は `PLAYER_QA_OUTPUT`。計測時だけStandalonePresentationSmoke.csを一時コピーし、プレイヤー起動時に `BBB_SMOKE_OUTPUT` を指定する。検証用セーブ以外で動作する入口は設けていない。

## 引き継ぐ判断

本編20敵・7武器・30背景の接続、Windows検証、実行時の支持足・打撃・飛翔・路面の修正までを今回の範囲とした。見本動画と本編の検査結果は別ファイルに保存した。歩行は原画16枚のコマ保持中の接地を補正する方式で、連続した全身骨格IKは使用していない。対象携帯端末での指操作・聴感と最終美術の採否は未確認。ストア配布と署名はこのWindows用隔離ビルドの対象外。
