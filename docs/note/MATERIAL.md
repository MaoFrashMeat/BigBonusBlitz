# MATERIAL.md — note の材料の割り当て表

記録の本体は `docs/devlog.md`（決定と理由）と外部知能の `errors/ERRORS.md`（失敗）。
**同じことをここに書き写さない。** このファイルが持つのは次の2つだけ。

1. 記事のどの節に、どの材料が入っているか（照合用）
2. まだ記事に入れていない材料の控え

---

## 追記の書式

新しいものを「未整理の材料」の先頭に足す。1件2行で足りる。

```
### YYYY-MM-DD [種別] 一言で
- 出どころ: devlog の日付 / ERRORS の番号 / 実測の条件
- 記事のどこに使えそうか:
```

種別と行き先。

| 種別 | 記事の行き先 |
|---|---|
| `失敗` | 6. 壊れた箇所カタログ |
| `仕組み` | 3〜5. 仕組み①②③ / 11. 効かなかったこと |
| `数字` | 各所 + 付録の出どころ表 |
| `決定` | 9. 今も直っていないもの / 各所 |
| `絵と音` | 8. 絵と音をどうしたか |

**数字は「いつ・どの条件で測ったか」ごと持ってくる。** 条件が違うと比較にならない
（記事の「何回まわせば足りるのか」がその実例）。

### 2026-09-10 [失敗] 例外1つが、別々に見える2つの不具合に化けた
- 何が起きたか: 「ボーナスを揃えると操作を受け付けない」「長押ししても自動が始まらない」の2件を、本人が別々に報告した。原因は同じ1箇所だった。画面更新の関数の中で、存在しない子要素を名前で探していて例外が出ていた。
- なぜ起きたか / どう直したか: 例外はそこで止まるので、その後ろにあるボタンの更新に処理が届かない。症状は「押しても何も起きない」なので、どの機能が壊れたのかが表に出ない。参照を先に持っておく形に直した。
- 記事のどこに使えそうか: 6. 壊れた箇所カタログ。AI が書いたコードのバグは「動かない」ではなく「静かに何も起きない」形で出る、という例

### 2026-09-10 [失敗] 自分で書いたUIルールを、書いた本人（AI）が翌日に破った
- 何が起きたか: 文字の重なりを何度も指摘されたので、AI に再発防止のルールを md にまとめさせた。そのあとアイコンを足す作業で、AI はその1番目のルールを破って同じ重なりを作った。本人から3度目の指摘を受けた。
- なぜ起きたか / どう直したか: 散文で書いたルールは、AI が読んでも守られない。重なりを機械的に計算して、あれば異常終了する検算スクリプトに置き換えた。作った直後に別の重なりを1件検出した。
- 記事のどこに使えそうか: 3〜5. 仕組み。「ルールを文章で書く」と「ルールを実行できる形にする」の差。効かなかった工夫の実例

### 2026-09-10 [失敗] 遊んでいても気づけない不整合を、通しテストが拾った
- 何が起きたか: 100万回転の通しテストで2件出た。ソウルの加算が画面側に報告されず吸収の演出が出ない（100万回中1252回）。装備を失うと松明の上限が下がるのに、残量が古い値のまま上限を超える（344回）。
- なぜ起きたか / どう直したか: どちらも遊んでいる分には破綻せず、数値がわずかにずれるだけなので目視では見つからない。毎回転ごとに「増えた量」と「実際の残高」が一致するかを機械が突き合わせて、初めて出た。両方その場で直した。
- 記事のどこに使えそうか: 3〜5. 仕組み。目視のテストと機械のテストで、見つかるバグの種類が違うという具体例

### 2026-09-10 [数字] 機械割の食い違いは、条件差ではなく測った時点の差だった
- 何が起きたか: 記事に書けなかった数字として「163.7% と 129.7% の食い違い、計測条件が違うと思われる」と保留していた。条件は同じ（設定1 / 200万回転 / ナビに従う）で、違ったのは測った時点。あいだに AT の出玉調整が入っていた。
- なぜ起きたか / どう直したか: 数字に日付を添えていなかったので、後から見ると条件差に見えた。現在値は設定1で165.3%。設定5が142.2%で設定1より低いという逆転がある（設定ごとの調整が未着手のため。本人了承済みの保留事項）。
- 記事のどこに使えそうか: 付録の出どころ表。数字には「いつ測ったか」も要る。条件だけでは足りない

### 2026-09-10 [絵と音] ポーズの骨組みが枠の上半分に寄っていて、歩きのコマの背丈がばらついた
- 何が起きたか: キャラを同一に保つため、先に棒人間のポーズ画像を作ってから絵を生成している。その棒人間が1024四方の上半分にしか描かれておらず、頭の点が枠の外に出ていた。結果、歩きの6コマで背の高さと向きが揃わない。
- なぜ起きたか / どう直したか: 座標を手で置いたときに、全身が枠に入るかを確認していない。まだ直していない。骨組みを作り直して34コマを再生成する（約10分）。本人の判断待ち。
- 記事のどこに使えそうか: 8. 絵と音をどうしたか。生成AIの絵は「1枚ずつは良いのに、並べると揃わない」形で失敗する

### 2026-09-10 [仕組み] 複数PCで作業すると、Unity が勝手にファイルを書き換えて同期を止める
- 何が起きたか: 別のPCの変更を取り込もうとしたら、5ファイルに未保存の変更があると言われて止まった。中身は Unity が画像の分割設定を自動で書き足したもので、こちらが触った覚えはない。
- なぜ起きたか / どう直したか: Unity は画像を読み込んだ時点で設定ファイルを自動で埋める。放置すると同期のたびにこの足止めが起きる。中身を見て、参照用のIDが変わっていないことを確認してから取り込んだ。同期の前に必ず一度保存する、という手順に落とした。
- 記事のどこに使えそうか: 3〜5. 仕組み。複数PC運用の実際のつまずき。「同期した」と「同じ状態になった」は別
