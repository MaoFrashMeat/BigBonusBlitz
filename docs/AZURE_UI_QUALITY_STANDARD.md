これは今後触る画面の既定品質。会話で再指定を待たず適用する。未改修の全画面がこの基準を満たしたという意味ではない。

## 画風と共通部品

| 要素 | 採用する設計 | 実装入口 |
|---|---|---|
| 世界 | 空・白い城塞・紺の布・金の紋章。装備は月夜、ステータスは宇宙 | 各画面の設計MD、既存Resources |
| 情報面 | 不透明な象牙色。暗い画面は不透明な紺。細い金線と局所的な飾り | AzureShopSkin.Surface |
| 主操作 | 金の明るいボタン、その他は紺。縁の金細工を維持 | AzureMapSkin.Button |
| 書体 | 題名・主要ラベルはNoto Serif JP、説明・細かな数値は読みやすい既存書体 | AzureMapSkin.Typography / AzureUiControls.Label |
| 区切り | 1pxの金線、小さな菱形。巨大な装飾を本文の裏に置かない | AzureUiControls.Rule |
| ON/OFF | 状態文字＋左右に移る白いつまみ。青/灰の色だけに依存しない | AzureUiControls.Switch |
| スライダー | 44pxの操作範囲、細いレール、青い宝石。レールとは独立したつまみ寸法 | AzureUiControls.Slider |
| 画面幅 | 1170×540の論理構成、親のSafeRootで縮小。旧960幅のタイトルからも収める | AzureScreenFit |

派手な背景の上に薄い半透明矩形を置く、単色の巨大パネルと既定UIだけで完成扱いする、別タブだけ紫やフラットな旧デザインへ戻る、といった状態を残さない。色は情報の役割に沿って統一する。危険な操作は破壊的であることと確認手順を保持する。

## 組み立てる順序

1. 実際の既存画面と参考を見て、主役・列構造・操作の優先順位を決める。
2. 実装の入口と保存・コールバック・確認・音・キーボード操作を読む。
3. 背景 / 枠 / 紋章 / UI文字 / 操作を分離。画像にライブの文字・価格・数値を焼き込まない。
4. 既存のAzure素材を先に検討。新規絵が必要なら内蔵画像生成を使い、PNG原本・保存先・プロンプトを記録する。
5. 列幅、余白、装飾の占有域を先に決める。金の唐草はRectTransformの端より内側へ入り込むため、本文はさらに内側に置く。
6. 全タブ・最大値・非表示・不足・確認・復帰を設計。同じ画面の一部だけを磨いて止めない。
7. 実データに接続してから隔離Unityで描画する。文字が見えるか、背景と紛れないか、装飾に接触しないかを目視して直す。

## 完了を判断する証拠

- Core/Runtime/Testsコンパイル、`docs/check_layout.py`。
- 1280×720 と2556×1179の実uGUI描画。デザイン見本やHTMLだけでは代用しない。
- 文字のpreferredHeight、空文字以外の描画頂点、兄弟ラベルの重複、44px以上の操作範囲を確認。小さな非操作のキー見本と実ボタンは区別する。
- スライダーは初期状態だけでなく最小・中間・最大へ動かした後のつまみ比率を確認。UnityのSlider.UpdateVisualsはアンカーを書き換える。
- 画面の入口が複数なら実際の呼び出し元でも確認する。特にタイトルは960幅、冒険・地図は1170幅。
- 画像を参考と見比べ、世界観・書体・余白・素材品質・状態表現の弱い箇所をもう一度直す。
- 検証したことと未確認を区別して引き継ぎへ残す。実機タッチ・聴感・配布ビルドを未検証のまま保証しない。
