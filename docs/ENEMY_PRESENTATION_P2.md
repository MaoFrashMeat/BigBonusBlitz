## 接続の決まり

1. 本体の倍率は個体単位で固定。伏せや潰れを同じ高さに拡大しない。足元を揃える処理と倍率を分ける。
2. 前の位置から現在コマの位置へSmoothStepで移動。空中にいるときは足元影を小さくする。人体や刀身をメッシュ変形しない。
3. `eventAt`はコマ内の0〜1。contactは踏み込みコマの85%で発火する。移動開始の瞬間に被弾させない。初稿の遠い位置から被弾した見え方は距離と発火位置を見直した。
4. 同じ攻撃の再要求で予兆を先頭へ戻さない。hitで攻撃を中断したら、元のcontactを後から発火しない。低FPSで複数コマを越えても同種イベントはTick内で一度にまとめる。
5. defeatは最終コマで止まる。idleの明示要求または個体切替だけで復帰する。勝手に待機へループさせない。

## 2026-09-28 本編接続前の調査

この段落はソース調査であり、敵を本編へ差し替えた記録ではない。主人公の接続は [HERO_GAMEPLAY_P2.md](HERO_GAMEPLAY_P2.md) へ進んだ。

- 本編 `enemy_tables.json` は通常とボスの計6件で、外見種はslime/goblin/bat。制作済み24ポーズはslime/goblin/wolf。**batをwolfへ黙って対応させない。** スライム/ゴブリンを先に接続し、未対応種は旧外見へ戻す。森狼は20敵計画の新IDとの対応を定義してから使う。
- `GameController.ShowEnemy` はImage差替え、色/倍率、SpawnEnemyRoutineの登場とIdleBobを持つ。新viewを子にする場合、色の継承と二重の上下動を明示的に扱う。虹色ヒント/ボス倍率を消さない。
- `BattleStartRoutine` にも敵Imageの直接差替えがあり、通常敵の入口だけではAT戦を覆えない。未対応種へ移った際に前のアニメ敵が残らないよう、開始時の有効化/無効化を共通化する。
- `EngageStepRoutine` と `BattleHitRoutine` は攻防と決着の別経路。表示contactからCoreのダメージ/抽選/報酬を追加しない。既存の結果が表示要求を発行する片方向の接続とする。
- 前兆の影とボーナスの3敵は別描画。対象を明記し、通常敵だけの接続を全敵対応と呼ばない。HideEnemy時は古い待機・虹色・攻撃コルーチンを止め、次の敵へ遅れて反映されないよう検証する。
